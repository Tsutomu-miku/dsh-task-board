# DSH 任务看板实施路线图

DSH 任务看板服务于本机 DSH 与 Codex 的任务调度、接力和代码验收。每张卡维持一条主时间线与一个输入框。执行器设置对应实际运行行为，核心执行链路经真实运行时验证。插件新增的 Git 资源需要同时提供查看、合回和清理方式。

## Phase 1 · 收敛任务与执行链路

- 新建任务只填写名称、说明、执行器和可选的自动运行。工作目录与 Git 工作区模式放进「运行设置」。
- 移除项目文档、独立讨论、唤醒、PR/CI 轮询、收件箱、通用命令执行器和扁平编排字段。忽略旧字段，保留 SQLite 卡片、会话、运行、历史附件和旧资源数据。
- 单一输入框负责发送、排队、插队、接管及 DSH 纠偏。通过「变更」按需查看本机 Git Diff。
- Codex 生产执行路径使用 `codex exec --json`。保留模型、角色指令、自动交接、单轮超时和 Token 上限。角色与写回提示只拼装一次。
- 独立验收覆盖真实 DSH 和 Codex CLI 的建卡、切换、交接、停止和恢复，以及表单和旧数据兼容性。

## Phase 2 · 并行与工作树交付

- 按目录显示等待原因，在顶栏列出并行运行的任务。
- 为独立工作树补上安全的合回和清理入口。检测原分支变化、未提交或未合入改动，避免覆盖当前目录。删除卡片前说明待处理的工作树。
- 独立验收覆盖多仓库并行，以及同仓库两张隔离任务从改动、合回到清理。

## Phase 3 · 单卡自治和消息附件

- 将现有写回传输改成本机受限回调，保留 `board_set_outcome`、`board_delegate` 和权限边界。
- 从主输入框粘贴或上传附件，随消息进入时间线，让两个执行器都能读取。
- 独立验收覆盖实现者和审查者在同卡接力、阻塞与恢复，以及真实图片输入。

第三方运行时和项目树分别需要独立设计。
